You are working on Pulse, a CLI for ML debugging.

Pulse is NOT a web dashboard and I do NOT want a GUI. I want you to redesign the **terminal/CLI UX** so that Pulse feels like a polished developer tool rather than a collection of raw `input()` prompts and print statements.

## IMPORTANT: PRESERVE THE EXISTING IMPLEMENTATION

Do NOT rewrite the CLI from scratch.

Do NOT remove existing functionality.

Do NOT simplify, shorten, or replace large sections of the code just to implement this.

Make surgical changes to the existing implementation.

Preserve:

* existing commands
* existing authentication behavior
* workspace behavior
* Supabase integration
* model configuration
* API-key handling
* GitHub commit handling
* `pulse run`
* runtime instrumentation
* auto-intervention behavior
* tracking behavior
* agent behavior
* error handling
* existing backend logic

The goal is primarily to improve **how the existing functionality is presented to the user in the terminal**.

Before modifying anything, inspect the existing CLI and understand how the current setup flow works.

---

# CURRENT SETUP FLOW

When a user starts Pulse, the current flow is approximately:

1. Sign up or log in
2. Select an existing workspace OR create a new workspace
3. Enter/provide the GitHub commit SHA
4. Select an agent model from a list of ~20 models
5. Enter the API key for that model
6. Start training / run the user's code
7. During training, Pulse may automatically intervene when it detects a problem

I want every one of these states to have a clean, cohesive terminal UI.

---

# DESIGN DIRECTION

Think:

**modern developer CLI**
+
**interactive terminal wizard**
+
**minimal / technical / premium**

NOT:

* web dashboard
* GUI
* giant ASCII art
* walls of text
* generic `input("Enter X: ")`
* excessive emojis
* giant decorative boxes everywhere
* 20 model cards
* unnecessary animations
* fake complexity

Pulse should feel like a serious ML debugging tool.

Use a consistent visual language throughout the entire setup flow.

For example:

```text
PULSE / WORKSPACE
PULSE / CODE VERSION
PULSE / AGENT MODEL
PULSE / API KEY
PULSE / RUN
PULSE / INVESTIGATION
PULSE / AUTO-INTERVENTION
```

Use concise status indicators:

```text
✓ completed
● currently happening
○ upcoming
⚠ anomaly
✕ failure
→ transition
```

Use color sparingly and consistently if the current CLI framework supports it.

One primary Pulse accent color is preferable to a rainbow of colors.

IMPORTANT:

The UI must reflect the ACTUAL state of Pulse.
